# Proposal

## Why

The tool can bake and preview but cannot fulfill its core promise: "your GLB,
plus AO". This change adds the export pipeline - surgical COLOR_0 injection
into the original glTF document via gltf-transform (D1), compressed-input
  support, and browser download - backed by round-trip regression tests.

## What Changes

- Load path extended to a dual-parse (docs/architecture.md "Dual-parse
  loading"): the same file bytes produce both the three.js preview scene and
  a gltf-transform Document; the Document is the export source of truth.
- Export: inject baked RGB values as COLOR_0 (VEC3 FLOAT) into each primitive,
  overwriting any existing COLOR_0 (D4), leaving every other part of the
  document untouched; serialize to GLB and download.
- Vertex correspondence between preview meshes and Document primitives is
  guarded by tests (both preserve primitive vertex order).
- Draco-compressed input support for preview and export (decoder assets
  bundled); meshopt already works from `scaffold-web-app`.
- Export button in the sidebar, enabled when a bake has completed.

## Capabilities

### New Capabilities

- `glb-export`: exports the loaded GLB with baked vertex colors added -
  fidelity of everything else, COLOR_0 correctness, compressed-input
  support, and download delivery.

### Modified Capabilities

- `model-viewer`: loading requirement extended - Draco-compressed GLBs are
  now loadable input (added as a new requirement to the existing
  capability; no existing requirement text changes).

## Impact

- New runtime dependency: `@gltf-transform/core` (+ `@gltf-transform/
  extensions` for Draco/meshopt handling). GLTFExporter is explicitly NOT
  used anywhere (D1).
- `src/loader/` returns both scene and Document; `src/export/` new module;
  `src/ui/` gains the export button.
- First binary test fixtures in the repo (tiny, generated by a script).
